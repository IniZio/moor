Conventions. Cov: BB = black-box test in `tests/task_cli.rs` / `tests/cli.rs` (named); INT = in-file `#[cfg(test)]` test (named `file::test`); none = no test found. UL-n = usage-log item n (`work/v1/evidence/c4/usage-log.md`; the log reuses numbers per drive section: 3g = 62-71, 3h = 72-80, 3i = 81-84, 3j = 85-88, 3j-b = 89-99). Flags: KNOWN-BUG (cites UL/BACKLOG), DESIGN-SMELL (works, but do not port as-is), SECURITY-INVARIANT (no-secret-in-Box / egress / scoping rule: the rewrite must have a parity test). `{...}` = cross-reference to the row id generated for a named row. Parity is behavioural: strings in quotes are pinned only where a test or doc pins them; other wording is advisory.

Scope findings. (1) The CLI is flat: `moor env`, `moor github setup|login`, `moor proxy check|serve`; there is NO `moor task ...` namespace (the request's `moor task env/proxy` = these). (2) `moor proxy serve` is hidden and is the per-Task supervisor, not a user command. (3) There is no refresh loop, no `GH_TOKEN` file and no token in the Box: the Box sees only the nonce, proxy URL, git insteadOf, push URL and a curl `gh` shim. (4) The proxy's upstream bases (`api.anthropic.com`, `github.com`, `api.github.com`) are hard-coded in `ProxyConfig::new`; `MOOR_GITHUB_API`/`MOOR_GITHUB_WEB` only affect the minting HTTP client. Hence ALL proxy forwarding behaviour (section 6) is INT-only today. (5) Several behaviours are only known from live drives (3g/3h/3i); they are marked `live-only`.
