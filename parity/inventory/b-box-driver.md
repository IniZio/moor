Inputs read: GLOSSARY.md, docs/adr/0001, README.md, skills/moor/SKILL.md, CLAUDE.md, src/driver.rs, src/crabbox.rs, src/hosts.rs, src/config.rs, src/gate.rs, src/policy.rs, src/provision.rs, src/env.rs (setup/teardown/record/cache), src/task.rs (give_box, run_setup, run, cp, close, promote), src/sleep.rs, src/pane.rs (shell), src/proxy_run.rs (tunnel supervisor), tests/task_cli.rs, `.groundwork/BACKLOG.md`, `.groundwork/work/v1/evidence/c4/usage-log.md`.

Conventions
- Parity is behavioural. CLI/JSON shape may change; the observable outcome in the Then column must survive.
- Coverage: `BB:` = black-box test in `tests/task_cli.rs` (drives the real `moor` binary against a fake `crabbox`/`herdr`; the fake `crabbox run` executes the script locally in the worktree). `INT:` = in-file `#[cfg(test)]` test (file named). `none` = no test.
- Flags: `KNOWN-BUG` cites `UL n` (usage-log item, `.groundwork/work/v1/evidence/c4/usage-log.md`) or `BL` (BACKLOG.md). `DESIGN-SMELL` = works, but shape conflicts with the Driver boundary rule or is incoherent; judgement by the inventory author.
- Box handle (registry `box.handle`) is `<provider>/<name>`; name is `moor-<task>-<6 hex>` (`box_name`). Registry `box` = `{driver:"crabbox", handle, state}`; states seen in code: `starting ready failed gone asleep stopped deleted release_failed`.
- Fake-crabbox log line format used by BB tests: `crabbox <subcommand> <args…>` (argv only; env visible via fake-written `SEED=` and `DELETE=` lines).

## 15. Crabbox contract (everything moor sends)

All calls use `MOOR_CRABBOX` (default `crabbox` on PATH), `current_dir = Task worktree` unless noted, `stdin = null`. Common env, set when applicable: `CRABBOX_CONFIG=<crabbox.yaml or .crabbox.yaml, worktree then main checkout>`; for provider `ssh` also `CRABBOX_STATIC_ID=<box name>`, `CRABBOX_STATIC_PORT=<ssh_port>`. moor never parses stdout of warmup, run, cp, stop, pause, resume, connect.

## 16. Gaps (no black-box test)

Behaviours with only INT coverage or none, grouped. A rewrite should add black-box tests (fake crabbox is in `tests/task_cli.rs`; it has no `ssh`, `pause`, `resume`, `providers`, `connect` handlers except a fake `ssh` installed by specific tests).

1. Sleep/wake against a Suspend provider (B-103 to B-106): the BB fake crabbox has no `providers`, `pause`, `resume`; only INT.
2. `crabbox list`-based gone reconciliation with real inventory (B-80), except the ssh-skip case.
3. Fresh-state prep and the lockfile cache beyond the trivial local-fake run (B-40 to B-47): INT shell tests only; no BB test checks the cache over two successive runs or the failure hint on stderr (B-33).
4. `sudo` ownership fixup (B-41): INT with stub sudo only.
5. Teardown timing and failure (B-56): one BB (`ssh_close_runs_teardown_after_reconcile`) covers the success path; failure message and events INT only.
6. `moor shell` (B-93): no test of the connect call at BB level; no wake.
7. Provision (B-50, B-51): INT only; no BB test, and sync of gitignored provisioned files to a real Box is unverified.
8. Egress on namespace-devbox (B-101): INT only; BB covers sprites and local-container.
9. Release outcome mapping (B-77, B-79): BB covers release failure warning on a `failed` Box only; the ready-Box release-error-aborts-close path and `NotFound` are INT.
10. Setup `tail`/`step`/`tail_error` payload (B-53): INT only (BB asserts only warning and Box state).
11. Box target cache (B-114), ssh 255 retry, read timeout kill (B-113): INT only.
12. `moor run` against a dead/disappeared Box: no coverage of crabbox failing mid-run, nor of the non-zero first-run `-1` failure (B-17).
13. `--record` with `--quiet`, interrupted record, and the registry row for interrupted runs (B-32).
14. Multiple Boxes per Task and provider quota refusal (B-94, B-96): no BB test of promotion after a provider refusal (BL known gap).
15. Dead-provisioning detection (B-76): INT with injected clock only.
16. Dotfiles upload (B-115) against ssh failure modes: BB covers dir/git forms with a fake ssh.
17. Reverse tunnel supervisor restart, backoff, max-unready (B-110): INT with fake clock; BB covers spawn-once and close only.
18. Static-ssh claim contention, `stop` leaving the workRoot dir (B-86): none; fork behaviour.

## 17. Cross-cutting notes for the rewrite

- Boundary smell summary (all DESIGN-SMELL above): moor's code names crabbox providers (`sprites`, `ssh`, `namespace-devbox`, `local-container`), crabbox env vars (`CRABBOX_STATIC_*`, `CRABBOX_NAMESPACE_*`, `CRABBOX_SYNC_GIT_SEED_SOURCE`), crabbox flags (`--reclaim`, `--no-hydrate`, `--class`, `--sprites-network-allow`), crabbox files (`crabbox.yaml`), and crabbox output text (prefix lists, "not found", exit 4). GLOSSARY and ADR 0001 say these should sit behind the Driver seam. The Driver trait also carries Engine/Credential concerns (`agent_command`, `check_credentials`, `probe_proxy`, `upload_dir`, `read_file`).
- Sync policy gaps (B-61 to B-64) are the largest functional pain in the usage log; they are crabbox-side but moor chooses when to sync (every `Driver.run`).
- `Driver.run` versus `Driver.exec`: `run` appends to a log file and has no quiet/echo handling; `exec` has quiet handling, interruption and exit-130 semantics. Setup, teardown and dotfiles use `run`; `moor run` and transcript use `exec`.
